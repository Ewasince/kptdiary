# Пакет для независимой реализации (handoff)

Здесь собрано всё, что было входом в разработку КПТ-дневника, чтобы ту же задачу можно было дать
другой модели или другому человеку и сравнить результат. Результат оригинальной разработки лежит в
этом же репозитории (ветка `master`); его не нужно показывать исполнителю, которого вы проверяете.

## Состав

| Путь | Что это | Роль |
| --- | --- | --- |
| `spec.md` | Спецификация системы | Главный документ. Отличается от `docs/superpowers/specs/…` только разделом 10 «Макеты», который заменяет ссылку на дизайн-холст |
| `materials/` | Материалы психотерапевта: протокол дисфункциональных мыслей (таблица, jpg) и перечень когнитивных ошибок | Контекст предметной области, спека на них ссылается |
| `mockups/` | Двенадцать утверждённых макетов, HTML + PNG | Внешний вид экранов. Имеют приоритет над текстом спеки в вопросах вёрстки |
| `skills/` | Копии скиллов плагина superpowers (MIT, см. `skills/LICENSE`), по которым шёл процесс | Процесс: план, субагенты, ревью, проверка перед сдачей |
| `tier-2-plan/plan.md` | План реализации, составленный оригинальным исполнителем по спеке | **Не давать на уровне B.** Только для облегчённого уровня C «исполнить готовый план» |

## Уровни проверки

- **B (основной)**: исполнитель получает `spec.md`, `materials/`, `mockups/`, `skills/` и промпт
  ниже. План он пишет сам.
- **C (облегчённый)**: то же плюс `tier-2-plan/plan.md`; проверяется только исполнение.

## Как это было пройдено оригинально

1. Интерактивный brainstorming с пользователем по скиллу `skills/brainstorming` дал спеку и макеты
   (в пакете уже готовые).
2. `skills/writing-plans` → план из 14 задач.
3. `skills/subagent-driven-development`: на каждую задачу свежий субагент-исполнитель
   (шаблон `implementer-prompt.md`), после каждой задачи свежий субагент-ревьюер
   (`task-reviewer-prompt.md`), при находках раунд исправлений и повторное ревью
   (`re-review-prompt.md`). Исполнители работали по `skills/test-driven-development`.
4. Ревью всей ветки по `skills/requesting-code-review/code-reviewer.md`, одна волна исправлений,
   повторное ревью.
5. `skills/verification-before-completion` и `skills/finishing-a-development-branch`: проверки,
   сборка, скриншоты экранов, пуш.

Все субагенты работали на одной модели. Ревьюеры не исправляют код сами.

## Промпт для исполнителя (уровень B)

Скопируйте в начало сессии вместе с содержимым папок.

> Ты разрабатываешь приложение «КПТ-дневник» в пустом git-репозитории (в нём только папки
> `materials/` и `docs/handoff/`). Спецификация: `docs/handoff/spec.md`, это обязательный документ;
> где спека говорит о внешнем виде, макеты в `docs/handoff/mockups/` имеют приоритет. Материалы
> предметной области: `docs/handoff/materials/`.
>
> Процесс: следуй скиллам из `docs/handoff/skills/`. Сначала `writing-plans`: составь план
> реализации по спеке и закоммить его в `docs/superpowers/plans/`. Затем выполняй план по
> `subagent-driven-development`: на каждую задачу отдельный субагент-исполнитель и отдельный
> субагент-ревьюер по шаблонам из той же папки; исполнители работают по `test-driven-development`.
> В конце ревью всей ветки по `requesting-code-review/code-reviewer.md`, одна волна исправлений по
> его находкам и повторное ревью. Перед сдачей `verification-before-completion`.
>
> Работай автономно: вопросов пользователю не задавай, спорные места решай сам, записывай каждое
> такое решение и в конце перечисли их списком с ценой ошибки. Коммить часто, пуш в ветку
> `<имя ветки>`. Pull request не создавай.
>
> Готово значит: `npm run check` (типы, линтер, тесты) и `npm run build` проходят; приложение
> запускается через `vite preview`; есть скриншоты всех экранов на 390 и 1280 px и отчёта A4, они
> совпадают с макетами; PWA устанавливается и работает офлайн; в репозитории есть воркфлоу деплоя
> на GitHub Pages и README на русском.

## Как сравнивать результаты

Оригинальная сборка: 26 коммитов, 242 теста, проверки и сборка зелёные, скриншоты совпадают с
макетами, финальное ревью нашло одну критичную находку (валидация импортируемого бэкапа) и пять
важных, все исправлены до сдачи. Сравнивать стоит по тем же осям: полнота спеки, тесты, что нашло
независимое ревью, сколько решений исполнитель принял сам и насколько они разумны.
