# КПТ-дневник: дизайн системы

Дата: 2026-10-20. Статус: утверждён в обсуждении, реализуется.

Макеты экранов: папка `mockups/` рядом с этим файлом, см. раздел 10 «Макеты». Макеты утверждены
пользователем и имеют приоритет над текстом спеки там, где речь о внешнем виде.

## 1. Цель и рамки

Личный дневник по «Протоколу дисфункциональных мыслей» (материалы в `materials/` рядом с этим файлом). Пользователь
один. Терапевт получает данные выгрузкой, в систему не заходит.

Требования:

- Заполнять с телефона (Android) и с компьютера, в том числе офлайн.
- Данные хранятся локально в браузере, сервера нет. Перенос между устройствами через файл бэкапа.
- Запись можно сохранить незавершённой (ситуация и эмоция сейчас, рациональный ответ потом).
- Быстрый ввод: пикер эмоций, слайдер с кнопками для уровней, запоминание своих эмоций.
- Два формата выгрузки: бэкап (JSON) и отчёт для терапевта (HTML, из него PDF через печать).
- Удаление записи.

Не делаем в первой версии (осознанно): пометки когнитивных ошибок у мыслей, статистика и графики,
синхронизация через сервер, тёмная тема, нативное приложение, двухколоночный режим на ПК.

## 2. Архитектура

Одностраничное приложение (SPA) на Vite + React 18 + TypeScript, устанавливается как PWA.
Хранилище: один JSON-документ в `localStorage`. Бэкенда нет. Деплой: статика на GitHub Pages
через GitHub Actions, базовый путь `/kptdiary/`.

Слои (каждый в своей папке, нижние не знают о верхних):

| Слой | Папка | Содержимое | Зависимости |
| --- | --- | --- | --- |
| model | `src/model/` | типы, создание записи, завершённость, каталог эмоций, шаг уровня, период, слияние, миграции | ничего |
| storage | `src/storage/` | чтение/запись `localStorage`, `navigator.storage.persist()`, скачивание и чтение файлов | model |
| report | `src/report/` | генерация самодостаточной HTML-строки отчёта | model |
| ui | `src/ui/` | React-компоненты, экраны, хэш-роутер, хук доступа к документу | model, storage, report |

Инструменты: Vitest + Testing Library + jsdom для тестов, ESLint + `tsc --noEmit` для проверки,
`vite-plugin-pwa` для манифеста и service worker. Пакетный менеджер npm, lock-файл в репозитории.
Файл `pyproject.toml` удаляется: Python в проекте не используется. Папка `materials/` остаётся.

Язык интерфейса: русский. Язык кода, идентификаторов и комментариев: английский.

## 3. Модель данных

```ts
interface Diary {
  schemaVersion: 1;
  entries: Entry[];
  customEmotions: CustomEmotion[];     // эмоции, введённые пользователем вручную
  lastReportExportAt: string | null;   // ISO datetime последней выгрузки отчёта
}

interface Entry {
  id: string;                 // UUID v4, стабильный, для слияния
  createdAt: string;          // ISO datetime, «когда случилось», редактируется пользователем
  updatedAt: string;          // ISO datetime последнего изменения, для слияния
  deletedAt: string | null;   // мягкое удаление: запись скрыта, но остаётся в документе
  situation: string;
  emotions: EmotionRating[];  // эмоции в момент ситуации
  thoughts: Thought[];
  outcomeEmotions: EmotionRating[]; // эмоции после рационального ответа
}

interface EmotionRating { name: string; intensity: number | null } // 1–100

interface Thought {
  id: string;                   // UUID v4
  text: string;                 // автоматическая мысль
  belief: number | null;        // 0–100 %, убедительность мысли до ответа
  response: string;             // рациональный ответ
  responseBelief: number | null;// 0–100 %, убедительность ответа
  beliefAfter: number | null;   // 0–100 %, убедительность мысли после ответа
}

interface CustomEmotion { name: string; family: EmotionFamily | null }
```

Соответствие колонкам бумажной таблицы: Ситуация → `situation`; Эмоции → `emotions`;
Автоматические мысли → `text` + `belief`; Рациональный ответ → `response` + `responseBelief`;
Результат → `beliefAfter` у каждой мысли и `outcomeEmotions` у записи.

Завершённость вычисляется, флага нет. Запись завершена, когда: `situation` непустая,
`emotions` непустой и у всех есть `intensity`, `thoughts` непустой и у каждой мысли заполнены
`text`, `belief`, `response`, `responseBelief`, `beliefAfter`, и `outcomeEmotions` непустой
с заполненными `intensity`. Незавершённые записи показываются с пометкой «Не завершена»;
завершённые без пометки.

Пустая запись (нет ситуации, эмоций и мыслей) при уходе с экрана записи удаляется физически,
она ещё нигде не могла оказаться. Любая непустая запись удаляется только мягко: `deletedAt` и
`updatedAt` получают текущее время. Удалённые записи не показываются нигде, кроме бэкапа.

Идентификаторы: `crypto.randomUUID()`.

## 4. Каталог эмоций

Файл `src/model/emotions.ts`. Структура по колесу Плутчика («цветок эмоций»): восемь семейств,
по три силы в каждом, и восемь смешанных эмоций между соседними семействами. Порядок семейств
по часовой стрелке с верхнего лепестка.

| Семейство (`family`) | Цвет | Слабая (1) | Базовая (2) | Сильная (3) |
| --- | --- | --- | --- | --- |
| `joy` радость | `#C94C8A` | безмятежность | радость | восторг |
| `trust` доверие | `#F2D63B` | принятие | доверие | восхищение |
| `fear` страх | `#C9C534` | тревога | страх | ужас |
| `surprise` удивление | `#4CB7C9` | возбуждение | удивление | изумление |
| `sadness` грусть | `#9FCBE5` | печаль | грусть | горе |
| `disgust` отвращение | `#7B8FD0` | скука | брезгливость | отвращение |
| `anger` гнев | `#E8A33A` | досада | злость | гнев |
| `anticipation` ожидание | `#E39ACB` | интерес | ожидание | настороженность |

Смешанные (между семействами, по часовой стрелке): любовь (радость+доверие), покорность
(доверие+страх), трепет (страх+удивление), разочарование (удивление+грусть), раскаяние
(грусть+отвращение), презрение (отвращение+гнев), агрессия (гнев+ожидание), оптимизм
(ожидание+радость). Смешанная эмоция хранит две семьи; её цвет это цвет первой семьи.

Эмоция в записи хранится по имени (`name`), в нижнем регистре, как в каталоге. Функция
`lookupEmotion(name, customEmotions)` возвращает семью, силу и цвет; для своей эмоции с
`family: null` цвет нейтральный серый `#9AA5AF`. Цвет чипа: фон это цвет семьи с прозрачностью
по силе (слабая 0.25, базовая 0.5, сильная 0.8), рамка цвет семьи, текст `#1F2328`.
Для смешанных прозрачность 0.4.

Своя эмоция добавляется из поля поиска пикера, когда введённого слова нет в каталоге и среди
своих. При добавлении можно выбрать лепесток (семью) или оставить без семьи. Свои эмоции
хранятся в `customEmotions` документа и попадают в бэкап.

«Недавние»: восемь имён эмоций, которые чаще всего встречались в записях за последние 30 дней,
а при равенстве те, что позже использованы. Вычисляется из записей, отдельно не хранится.

## 5. Экраны и поведение

Роутинг по хэшу: `#/` список, `#/entry/:id` запись, `#/export` экспорт. Пикер эмоций это
модальное состояние внутри экрана записи, не маршрут. Отчёт открывается отдельной страницей
(blob URL), не маршрут.

Адаптивность: одна колонка везде. До 900 px телефонная раскладка (как на макетах 390 px): нижняя
навигация «Записи / Экспорт», шторка пикера снизу. От 900 px раскладка ПК: верхняя панель с
навигацией и кнопкой «Новая запись», контент шириной до 1040 px по центру, пикер в модальном
окне, строки списка в сетку, компонент уровня в строчной раскладке.

### 5.1 Список записей (`#/`)

Записи без `deletedAt`, сортировка по `createdAt` по убыванию, сгруппированы по дням с
заголовками «Сегодня, 20 октября», «Вчера, 19 октября», далее «17 октября». Карточка: время,
первая строка ситуации (обрезается многоточием), чипы эмоций с интенсивностью. Если есть
`outcomeEmotions`, показывается пара «было → стало» для эмоций, которые есть в обоих списках,
в одну строку без переноса; остальные эмоции чипами. Незавершённая запись помечена жёлтым
бейджем «Не завершена». На ПК карточка это сетка: время, ситуация, колонка эмоций фиксированной
ширины 360 px с выравниванием влево; бейдж в правом краю колонки эмоций.

Кнопка «Новая запись» создаёт запись с `createdAt = now` и открывает её. Пустой список
показывает подсказку «Записей пока нет» и ту же кнопку.

### 5.2 Запись (`#/entry/:id`)

Одна длинная форма, без шагов. Сверху: назад, поле даты и времени (`datetime-local`,
меняет `createdAt`), кнопка удаления с подтверждением (`confirm`). Внизу кнопка «Готово» (возврат
к списку) и подпись «Изменения сохраняются автоматически».

Секции:

1. Ситуация: textarea с подсказкой.
2. Эмоции: выбранные чипы с крестиком (убрать) и пунктирная кнопка «+ Добавить эмоцию», которая
   открывает пикер. Под чипами компонент «уровень» для каждой выбранной эмоции (1–100).
3. Автоматические мысли: карточка на мысль. В ней: textarea мысли, уровень «Насколько
   убедительна» (0–100 %), разделитель, textarea «Рациональный ответ», уровни «Убедительность
   ответа» и «Мысль убедительна сейчас». Кнопка «×» удаляет мысль. Кнопка «+ Ещё мысль». На ПК
   мысль и ответ стоят в двух колонках, уровни под ними на всю ширину карточки. Если в карточке
   ответ или переоценка не заполнены, под ней подпись «Ответ и переоценка ещё не заполнены».
4. Результат: тот же блок выбора эмоций и уровней, что в секции 2, но пикер открывается с
   подсветкой эмоций из секции 2 в «Недавних» первыми.

Автосохранение: каждое изменение формы обновляет запись в документе (`updatedAt = now`), запись в
`localStorage` с задержкой 300 мс после последнего изменения. Несохранённого состояния у формы
нет.

### 5.3 Компонент «уровень» (IntensityControl)

Свойства: `label`, `value: number | null`, `min` (1 для эмоций, 0 для процентов), `max = 100`,
`unit` («» или «%»), `onChange(value)`. Содержит: подпись, слайдер (`input[type=range]`), поле
ввода числа (`input[type=number]`) и шесть кнопок «−10 −5 −1 +1 +5 +10». Текст кнопок минусов
красный `#A12F2F`, плюсов зелёный `#1E6B3A`, фон белый, рамка серая.

Правило кнопок при текущем значении `v` и шаге `n`:

- `±1`: `v ± 1`.
- `+5`, `+10`: следующее число, кратное шагу и строго большее `v`. 67 → 70, 70 → 75.
- `−5`, `−10`: ближайшее число, кратное шагу и строго меньшее `v`. 67 → 65, 70 → 65.
- Результат ограничивается в `[min, max]`.
- Если `value === null`, кнопки и слайдер отталкиваются от 50; первое же действие записывает
  значение.

Поле ввода принимает только целые числа в диапазоне; нечисловой ввод игнорируется.

Раскладка: телефон (`stack`): подпись и число в одной строке, слайдер под ними, кнопки сеткой на
всю ширину. ПК (`row`): подпись слева, в середине слайдер и под ним кнопки по центру шириной до
420 px, число справа. Выбор раскладки по ширине окна (900 px).

### 5.4 Пикер эмоций

На телефоне шторка снизу на 90 % высоты, на ПК модальное окно 980 px. Содержимое:

- Заголовок «Эмоции», переключатель вида «Цветок / Список», поле поиска, кнопка «Готово».
- Поиск фильтрует все эмоции (каталог и свои) по подстроке без учёта регистра; совпадения
  показываются чипами. Если точного совпадения нет, показывается кнопка «Добавить „слово“» и
  ряд лепестков для выбора семьи (можно пропустить). После добавления эмоция сразу выбрана.
- Вид «Цветок» (по умолчанию): SVG с восемью лепестками, подписями базовых эмоций внутри
  лепестков и подписями смешанных эмоций между лепестками, внутри пунктирного круга. Лепестки
  и смешанные подписи кликабельны. Тап по лепестку выделяет семью: лепесток остаётся ярким,
  остальные бледнеют (прозрачность 0.32), подписи соседних смешанных эмоций тёмные, остальные
  серые. Под цветком: заголовок семьи с цветной точкой и чипы трёх сил от слабой к сильной,
  разделитель, две смешанные эмоции с соседями пунктирными чипами. Тап по чипу включает или
  выключает эмоцию. Тап по смешанной подписи на цветке сразу переключает эту эмоцию. На ПК
  цветок слева (540 px), справа чипы выбранной семьи, блок «Выбрано в этой записи» и «Недавние».
- Вид «Список»: группы «Недавние», восемь семейств (три силы и смешанные с соседом справа),
  «Свои». Все чипы переключаемые.
- Выбранные эмоции в обоих видах закрашены цветом семьи. Чип выбранной эмоции помечен
  `aria-pressed`.
- «Готово» и закрытие шторки сохраняют выбор. Снятие выбора эмоции удаляет её оценку из записи.

Геометрия цветка: viewBox 440×440, центр (220, 220), лепесток это эллипс rx 38, ry 78 с центром
на расстоянии 78 от центра, повёрнутый на 45°·k; подписи базовых эмоций на радиусе 90, смешанных
на радиусе 161, пунктирный круг радиуса 180. SVG рисуется в коде, по данным каталога, без ручных
координат в разметке. Кликабельные элементы в SVG это `<a>`/`<button>`-подобные группы с
`role="button"`, `tabindex` и обработкой Enter.

### 5.5 Экспорт (`#/export`)

Два блока.

Отчёт для терапевта: пресеты периода чипами «День», «Неделя», «Месяц», «Всё время»,
«С последней выгрузки», и поля дат «С» и «По». Пресет подставляет даты, их можно править.
Определения: «День» это сегодня; «Неделя» последние 7 дней включая сегодня; «Месяц» последние 30
дней; «Всё время» от самой ранней записи; «С последней выгрузки» от даты `lastReportExportAt`
(пресет недоступен, если выгрузок не было). Под пресетами: «В период попадает N записей, из них M
незавершённые» и «Последняя выгрузка отчёта: дата». Кнопки: «Открыть отчёт» (новая вкладка),
«Сохранить HTML» (скачать файл `kptdiary-report-ГГГГ-ММ-ДД.html`), «Сохранить PDF» (открыть
отчёт и вызвать печать). Любая из трёх кнопок записывает `lastReportExportAt = now`.

Бэкап и перенос: «Скачать JSON» и «Импортировать», строка «Последний бэкап: дата, N дней назад»
(дата последнего скачивания хранится в `localStorage` отдельным ключом, в документ не входит).

### 5.6 Отчёт для терапевта

Модуль `report` получает список записей за период и возвращает строку HTML: самодостаточная
страница, стили инлайном, без внешних ресурсов, шрифт системный. Заголовок: «Протокол
дисфункциональных мыслей», период, количество записей и завершённых. Далее карточка на запись
по `createdAt` по возрастанию: дата и время, пометка «Не завершена» если нужно, строка
«Ситуация», строка «Эмоции» чипами, таблица мыслей с колонками «Автоматическая мысль»,
«Рациональный ответ» (в скобках «ответ: N%»), «Убедительность мысли: до → после», строка
«Эмоции: до → после» (пары одинаковых эмоций до и после; эмоции только из одного списка
показываются отдельно). Пустые поля подписаны «не записано», числа «—». Подвал: дата
формирования. Печать: `@page` A4 с полями 16 мм, карточка не разрывается (`break-inside: avoid`),
цвета сохраняются (`print-color-adjust: exact`). В отчёт попадают все записи периода, включая
незавершённые, кроме удалённых. Текст пользователя экранируется.

## 6. Хранение, бэкап, слияние

Хранилище: ключ `kptdiary.diary` в `localStorage`, значение JSON документа `Diary`. Загрузка при
старте; если ключа нет, создаётся пустой документ. Если JSON битый, приложение показывает
сообщение и предлагает импортировать бэкап, старое значение не перезаписывается, пока
пользователь не создаст запись. Запись после каждого изменения с задержкой 300 мс. При старте
вызывается `navigator.storage.persist()`, результат только логируется.

Бэкап: файл `kptdiary-ГГГГ-ММ-ДД.json`, содержимое `Diary` плюс поле `exportedAt`. Скачивание
через `Blob` и временную ссылку.

Импорт: пользователь выбирает файл; читаем, парсим, проверяем форму (`schemaVersion` число,
`entries` массив). Если `schemaVersion` больше текущей, отказ с сообщением «Файл из более новой
версии приложения». Если меньше, миграция. Затем сводка: «Новых записей: N, обновлённых: M,
своих эмоций: K» и кнопка «Применить». Применение заменяет документ результатом слияния.

Слияние `merge(local, incoming) → Diary` (чистая функция):

- Записи сопоставляются по `id`. Есть только в одной стороне: берётся как есть. Есть в обеих:
  берётся та, у которой `updatedAt` позже; при равенстве локальная. Мягко удалённая запись это
  обычная запись с `deletedAt`, правило то же, поэтому удаление с более поздним `updatedAt`
  побеждает, а правка после удаления на другом устройстве возвращает запись.
- `customEmotions` объединяются по имени; при конфликте семьи берётся локальная.
- `lastReportExportAt` берётся более поздняя из двух.
- Порядок записей в результате не важен, UI сортирует сам.

Миграции: `migrate(raw: unknown) → Diary` по цепочке версий. Сейчас одна версия; функция
существует, чтобы следующая версия добавила шаг.

Ошибки: переполнение `localStorage` (`QuotaExceededError`) показывает плашку «Не удалось
сохранить, место закончилось. Сделайте бэкап» и не теряет данные в памяти до перезагрузки.

## 7. PWA, сборка, деплой

- `vite-plugin-pwa`: манифест с именем «КПТ-дневник», коротким именем «Дневник», иконками
  192 и 512 px (простая монохромная иконка, SVG в репозитории и PNG в сборке), `display:
  standalone`, `orientation: portrait`, цвет темы `#2F6B8C`. Service worker кэширует все файлы
  сборки (precache). Стратегия обновления `registerType: 'prompt'`: при новой версии в приложении
  плашка «Доступно обновление» с кнопкой «Обновить». Google Fonts не используются, шрифт
  системный, чтобы офлайн выглядел так же, как онлайн.
- Сборка: `npm run build` в `dist/`. Базовый путь `/kptdiary/` берётся из `vite.config.ts`
  и может быть переопределён переменной `VITE_BASE` для другого хостинга.
- Деплой: `.github/workflows/deploy.yml` на пуш в `master`: установка, `npm run check`
  (`tsc`, `eslint`, `vitest run`), сборка, публикация `dist/` на GitHub Pages.
- Скрипты `package.json`: `dev`, `build`, `preview`, `test`, `lint`, `typecheck`, `check`.

## 8. Тестирование

- `model`: создание записи, `isComplete` на граничных случаях, шаг уровня (таблица примеров
  67/70/0/100, null), период для каждого пресета, слияние (новые, обновлённые, удалённые,
  конфликт `updatedAt`, объединение своих эмоций), миграция и отказ по версии, каталог
  (поиск, соседи семейств, цвета, «недавние»).
- `report`: рендер строки, наличие ключевых фрагментов (период, ситуация, пары «до → после»,
  пометка незавершённости), экранирование `<script>` в тексте пользователя.
- `storage`: чтение и запись в `localStorage` (jsdom), поведение на битом JSON.
- `ui` (Testing Library): создать запись и увидеть её в списке; открыть пикер, выбрать лепесток
  и чип, увидеть компонент уровня; добавить свою эмоцию через поиск; кнопки ±N меняют число;
  добавить вторую мысль; удалить запись с подтверждением; импорт файла показывает сводку и
  применяет слияние; пресет периода подставляет даты.
- Ручная проверка после сборки: скриншоты экранов в Chromium на 390 и 1280 px, сверка с макетами;
  установка PWA и офлайн-запуск проверяются на телефоне пользователем.
